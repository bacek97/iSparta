# Краткие Ответы

## 1. Почему Web Crypto API не соответствует BIP39?

**BIP39 - это не алгоритм, а стандарт генерации ключей из мнемоники:**

```
BIP39:     Мнемоника → Seed → BIP32 → BIP44 → secp256k1 ключи
                ↓
        "mountain pilot push"
                ↓
        Всегда одни и те же ключи (детерминированно)

Web Crypto: crypto.subtle.generateKey() → Случайные ключи
                ↓
        Каждый раз новые ключи (недетерминированно)
```

**Web Crypto API НЕ поддерживает:**
- ❌ `mnemonicToSeed()` - конвертация мнемоники в seed
- ❌ BIP32 - иерархическая деривация ключей
- ❌ BIP44 - стандартные пути (m/44'/0'/0'/0/0)
- ❌ secp256k1 - кривая Bitcoin/Ethereum

## 2. В чём отличие алгоритмов?

### Доступные в Web Crypto API:

| Алгоритм | Назначение | Скорость | Размер ключа | Для вашей задачи |
|----------|------------|----------|--------------|------------------|
| **ECDSA** | Подпись | Быстро | 91 байт | ✅ **Лучший** |
| **RSA-PSS** | Подпись | Медленно | 256+ байт | ⚠️ Медленно |
| **RSASSA-PKCS1-v1_5** | Подпись | Медленно | 256+ байт | ⚠️ Медленно |
| **HMAC** | Подпись | Очень быстро | 32 байта | ❌ Симметричный |
| **Ed25519** | Подпись | Очень быстро | 32 байта | ⚠️ Новые браузеры |
| **X25519** | Шифрование | - | 32 байта | ❌ Не для подписи |

### Детали:

**ECDSA (Elliptic Curve Digital Signature Algorithm):**
- Асимметричная криптография
- Публичный ключ на сервере, приватный у пользователя
- Кривые: P-256, P-384, P-521
- **Выбрал потому что:** Быстро + маленький ключ + работает везде

**RSA:**
- Асимметричная криптография
- Большие ключи (2048-4096 бит)
- Медленнее ECDSA
- **Не выбрал:** Избыточно для вашей задачи

**HMAC:**
- Симметричная криптография
- Один секретный ключ для подписи и проверки
- **Не выбрал:** Нужно хранить секрет на сервере (небезопасно)

**Ed25519:**
- Современная эллиптическая кривая
- Самый быстрый алгоритм
- **Не выбрал:** Не поддерживается в большинстве браузеров

## 3. Почему я выбрал ECDSA?

### Критерии выбора:

| Критерий | ECDSA | RSA | HMAC | Ed25519 |
|----------|-------|-----|------|---------|
| **Асимметричный** | ✅ | ✅ | ❌ | ✅ |
| **Быстрый** | ✅ | ❌ | ✅ | ✅ |
| **Маленький ключ** | ✅ | ❌ | ✅ | ✅ |
| **Поддержка браузеров** | ✅ | ✅ | ✅ | ❌ |
| **Встроен в Web Crypto** | ✅ | ✅ | ✅ | ⚠️ |

**Вывод:** ECDSA - лучший баланс для вашей задачи!

## 4. Схема работы

### Ваша публикация:

```typescript
{
    publicKey: 'base64',      // Публичный ключ автора
    signature: 'base64',      // Подпись данных
    date: new Date(),
    text: 'Great workout!',
    exercises: [...],
    image: 'base64/png'
}
```

### Процесс:

```
1. КЛИЕНТ (браузер):
   ├─ Генерация ключей (один раз)
   │  └─ crypto.subtle.generateKey("ECDSA P-256")
   │
   ├─ Создание публикации
   │  └─ { date, text, exercises, image }
   │
   ├─ Подпись данных
   │  └─ signature = sign(data, privateKey)
   │
   └─ Отправка в Hasura
      └─ { publicKey, signature, data }

2. HASURA:
   └─ Вызов Action → Deno Deploy

3. DENO DEPLOY:
   ├─ Проверка подписи
   │  └─ verify(signature, data, publicKey)
   │
   └─ Если ОК → вернуть данные

4. HASURA:
   └─ Вставка в БД
      └─ { publicKey, date, text, exercises, image, verifiedAt }
```

## ✅ Итого

**Вопрос:** Почему Web Crypto не соответствует BIP39?
**Ответ:** BIP39 - это стандарт генерации ключей из мнемоники. Web Crypto API генерирует случайные ключи, не поддерживает BIP32/BIP44 и secp256k1.

**Вопрос:** В чём отличие алгоритмов?
**Ответ:** ECDSA - асимметричный, быстрый, маленький ключ. RSA - медленный, большой ключ. HMAC - симметричный. Ed25519 - новый, не везде поддерживается.

**Вопрос:** Почему выбрал ECDSA?
**Ответ:** Лучший баланс: асимметричный + быстрый + маленький ключ + работает везде.
