# Варианты БЕЗ Внешнего Хостинга

## Вы правы - serverless это тоже хостинг!

Если вам нужно **полностью без внешнего хостинга**, есть только 2 реальных варианта:

---

## ✅ Вариант 1: PostgreSQL + Ed25519 (Рекомендую)

### Что меняется:

| Было (secp256k1) | Станет (Ed25519) |
|------------------|------------------|
| BIP39 → secp256k1 | BIP39 → Ed25519 |
| Проверка на внешнем сервере | Проверка в PostgreSQL |
| Hasura Action | Hasura Tracked Function |

### Преимущества:

- ✅ **Полностью без внешнего хостинга**
- ✅ **Проверка подписи в PostgreSQL** (через расширение `pgsodium`)
- ✅ **Бесплатно** (только PostgreSQL)
- ✅ **Быстрее** (нет HTTP запросов)

### Недостатки:

- ⚠️ **Нужно сменить алгоритм** с secp256k1 на Ed25519
- ⚠️ **Не совместимо с BIP44** (стандартные криптовалютные кошельки)
- ⚠️ **Требует расширение pgsodium** (не все хостинги поддерживают)

### Поддержка pgsodium:

| Хостинг | pgsodium |
|---------|----------|
| Supabase | ✅ Да |
| Neon | ❌ Нет |
| Railway | ✅ Да (нужно установить) |
| Render | ✅ Да (нужно установить) |
| AWS RDS | ✅ Да (нужно установить) |

### Настройка:

1. **Установить pgsodium в PostgreSQL:**
   ```sql
   CREATE EXTENSION IF NOT EXISTS pgsodium;
   ```

2. **Создать функцию проверки** (см. `postgres-ed25519.sql`)

3. **Track функцию в Hasura Console**

4. **Использовать Ed25519 на клиенте** (см. `client-ed25519.ts`)

### Код:

```typescript
// Клиент
import { signDataEd25519 } from './client-ed25519';

const { publicKey, signature } = await signDataEd25519(mnemonic, data);

// Отправить в Hasura (функция проверит подпись в PostgreSQL)
```

## ❌ Вариант 2: Проверка на клиенте (НЕ БЕЗОПАСНО!)

Можно проверять подпись на клиенте, но это **не защищает** от атак:

```typescript
// Клиент проверяет подпись
const isValid = verifySignature(data, signature, publicKey);

if (isValid) {
    // Отправить в Hasura БЕЗ проверки на сервере
}
```

**Проблема:** Злоумышленник может:
1. Открыть DevTools
2. Изменить код проверки
3. Отправить поддельные данные

**Вывод:** Это НЕ решение для безопасности!

---

## 🤔 Что выбрать?

### Если вам нужна БЕЗОПАСНОСТЬ:

| Требование | Решение |
|------------|---------|
| **Без внешнего хостинга** | PostgreSQL + Ed25519 |
| **Совместимость с BIP39/BIP44** | Serverless (Vercel/Cloudflare) |
| **Максимальная простота** | Serverless (Vercel/Cloudflare) |

### Моя рекомендация:

**Используйте Vercel Functions**, потому что:

1. ✅ **Бесплатно** (100k запросов/месяц достаточно для большинства проектов)
2. ✅ **Деплой за 1 команду** (`vercel --prod`)
3. ✅ **Совместимо с BIP39** (secp256k1)
4. ✅ **Не нужно менять алгоритм**
5. ✅ **Автоматический HTTPS**

Да, это "хостинг", но вы:
- Не настраиваете сервер
- Не платите за сервер (в пределах лимита)
- Не обслуживаете сервер
- Просто деплоите код

## 🎯 Итого

Если вам **критично важно** избежать любого внешнего хостинга:
- Используйте **PostgreSQL + Ed25519** (см. `postgres-ed25519.sql` и `client-ed25519.ts`)
- Убедитесь, что ваш PostgreSQL хостинг поддерживает `pgsodium`

Если вам важна **простота и совместимость с BIP39**:
- Используйте **Vercel Functions** (да, это хостинг, но бесплатный и простой)
