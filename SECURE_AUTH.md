# Безопасная Авторизация с BIP39

## Проблема: Перехват Публичного Ключа

❌ **НЕБЕЗОПАСНО**: Просто отправлять публичный ключ на сервер
```
Клиент → [publicKey] → Сервер
         ↑ ПЕРЕХВАТ!
    Злоумышленник может использовать этот ключ
```

## Решение: Challenge-Response с Криптографической Подписью

✅ **БЕЗОПАСНО**: Использовать цифровую подпись для доказательства владения приватным ключом

### Как это работает

```
1. РЕГИСТРАЦИЯ (один раз)
   Клиент → [publicKey] → Сервер (сохраняет в БД)

2. ВХОД В СИСТЕМУ
   
   Шаг 1: Сервер генерирует случайный challenge
   Сервер → [challenge: "a3f5b2..."] → Клиент
   
   Шаг 2: Клиент подписывает challenge своим ПРИВАТНЫМ ключом
   Клиент создаёт: signature = sign(challenge, privateKey)
   
   Шаг 3: Клиент отправляет подпись
   Клиент → [publicKey, signature] → Сервер
   
   Шаг 4: Сервер проверяет подпись
   Сервер: verify(signature, challenge, publicKey) === true?
   
   ✅ Если подпись валидна → пользователь доказал владение приватным ключом
   ❌ Если подпись невалидна → отклонить вход
```

## Почему это безопасно?

### 1. **Challenge каждый раз новый**
- Сервер генерирует случайный challenge при каждой попытке входа
- Старые подписи нельзя использовать повторно (защита от replay-атак)

### 2. **Приватный ключ никогда не передаётся**
- Клиент использует приватный ключ только для создания подписи
- Приватный ключ остаётся на устройстве пользователя
- Из подписи невозможно восстановить приватный ключ

### 3. **Публичный ключ можно перехватить, но это бесполезно**
- Злоумышленник может видеть публичный ключ
- Но без приватного ключа он не может создать валидную подпись
- Каждый новый challenge требует новую подпись

## Пример Атаки (которая провалится)

```typescript
// Злоумышленник перехватил публичный ключ
const stolenPublicKey = "03a1b2c3...";

// Сервер отправляет новый challenge
const challenge = "d4e5f6...";

// Злоумышленник пытается создать поддельную подпись
const fakeSignature = "deadbeef...";

// Сервер проверяет
verifySignature(challenge, stolenPublicKey, fakeSignature);
// → false ❌

// Почему провалилось?
// Для создания валидной подписи нужен ПРИВАТНЫЙ ключ,
// который есть только у настоящего владельца мнемоники!
```

## Математика (упрощённо)

### Создание подписи (на клиенте)
```
signature = ECDSA_sign(hash(challenge), privateKey)
```

### Проверка подписи (на сервере)
```
isValid = ECDSA_verify(signature, hash(challenge), publicKey)
```

**Важно**: Из `signature` и `publicKey` математически невозможно вычислить `privateKey` (проблема дискретного логарифма на эллиптических кривых).

## Flow Диаграмма

```
┌─────────┐                           ┌─────────┐
│ Клиент  │                           │ Сервер  │
└────┬────┘                           └────┬────┘
     │                                     │
     │ 1. Регистрация                      │
     ├──────── publicKey ─────────────────>│
     │                                     │ (сохраняет в БД)
     │                                     │
     │ 2. Вход в систему                   │
     │<─────── challenge ──────────────────┤
     │                                     │
     │ (подписывает challenge)             │
     │ signature = sign(challenge, privKey)│
     │                                     │
     ├─── publicKey + signature ──────────>│
     │                                     │
     │                                     │ (проверяет)
     │                                     │ verify(sig, challenge, pubKey)
     │                                     │
     │<──────── ✅ SUCCESS ────────────────┤
     │                                     │
```

## Код

### Регистрация
```typescript
// Клиент
const publicKey = await registerUser(mnemonic);

// → Отправить на сервер
// → Сервер сохраняет: { userId: 123, publicKey: "03a1b2..." }
```

### Вход
```typescript
// 1. Сервер генерирует challenge
const challenge = generateChallenge(); // "a3f5b2c3..."

// 2. Клиент подписывает
const { publicKey, signature } = await signChallenge(mnemonic, challenge);

// 3. Сервер проверяет
const isValid = verifySignature(challenge, publicKey, signature);
if (isValid && publicKey === storedPublicKey) {
    // ✅ Авторизация успешна
    createSession(userId);
} else {
    // ❌ Отклонить
}
```

## Дополнительная Безопасность

### 1. **Время жизни challenge**
```typescript
// Сервер сохраняет challenge с timestamp
challenges.set(challenge, { 
    createdAt: Date.now(),
    expiresIn: 60000 // 1 минута
});

// При проверке
if (Date.now() - challenge.createdAt > challenge.expiresIn) {
    throw new Error('Challenge expired');
}
```

### 2. **Rate limiting**
```typescript
// Ограничить количество попыток входа
const attempts = loginAttempts.get(publicKey) || 0;
if (attempts > 5) {
    throw new Error('Too many attempts, try again later');
}
```

### 3. **HTTPS обязательно**
- Весь трафик должен идти через HTTPS
- Защита от MITM-атак

## Сравнение с Традиционными Методами

| Метод | Что хранится на сервере | Что передаётся | Безопасность |
|-------|------------------------|----------------|--------------|
| **Пароль** | Hash пароля | Пароль (!) | ⚠️ Пароль может быть перехвачен |
| **JWT Token** | Secret key | Token | ⚠️ Token может быть украден |
| **BIP39 + Подпись** | Публичный ключ | Подпись challenge | ✅ Приватный ключ никогда не передаётся |

## Преимущества BIP39

1. ✅ **Нет базы паролей** - нечего утекать при взломе сервера
2. ✅ **Пользователь контролирует ключи** - мнемоника только у пользователя
3. ✅ **Совместимость** - стандарт BIP39 используется в криптовалютах
4. ✅ **Восстановление** - мнемонику легко записать и восстановить
5. ✅ **Математически доказуемая безопасность** - основана на ECDSA
