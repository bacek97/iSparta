## Ответ на ваш вопрос

### Как получить публичный ключ для хранения на сервере?

```typescript
import * as bip39 from '@scure/bip39';
import { wordlist } from '@scure/bip39/wordlists/english.js';
import { HDKey } from '@scure/bip32';

// 1. У вас есть мнемоническая фраза
const mnemonic = "word1 word2 word3 ...";

// 2. Конвертируем в seed
const seed = await bip39.mnemonicToSeed(mnemonic, '');

// 3. Создаем HD кошелек
const hdKey = HDKey.fromMasterSeed(seed);

// 4. Деривация по стандартному пути
const derivedKey = hdKey.derive("m/44'/0'/0'/0/0");

// 5. ПОЛУЧАЕМ ПУБЛИЧНЫЙ КЛЮЧ
const publicKey = Buffer.from(derivedKey.publicKey!).toString('hex');

// 6. Этот ключ можно безопасно хранить на сервере!
console.log('Публичный ключ:', publicKey);
// Пример: 0235c92b1391b40d229cfe9d257bfdd1bc3e699185be1d7d13dc5dc92b2ce5d4e3
```

### Что хранить на сервере?

**Вариант 1: Публичный ключ (рекомендуется)**
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    public_key VARCHAR(66) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);
```

**Формат:** Hex строка, 66 символов (33 байта)
**Пример:** `0235c92b1391b40d229cfe9d257bfdd1bc3e699185be1d7d13dc5dc92b2ce5d4e3`

### Процесс авторизации

1. **Регистрация:**
   - Пользователь генерирует мнемонику на клиенте
   - Клиент получает публичный ключ из мнемоники
   - Публичный ключ отправляется на сервер
   - Сервер сохраняет публичный ключ в БД

2. **Авторизация:**
   - Пользователь вводит мнемонику
   - Клиент генерирует публичный ключ
   - Публичный ключ отправляется на сервер
   - Сервер сравнивает с сохраненным ключом
   - Если совпадает → авторизация успешна

## Безопасность

### ✅ Безопасно:
- Хранение публичного ключа на сервере
- Передача публичного ключа по HTTPS
- Из публичного ключа НЕВОЗМОЖНО получить приватный ключ

### ❌ НИКОГДА не делайте:
- НЕ храните мнемонику на сервере
- НЕ храните seed на сервере
- НЕ храните приватный ключ на сервере
- НЕ передавайте мнемонику по сети
